# Paper Plane Run — complete experience redesign

## Direction

A handcrafted paper adventure: ivory stock, deep ink, rust-red actions, airy
blue scenery, expressive folds, and an editorial aviation-club composition.
The brand stays Paper Plane Run. Georgia display type and Nunito interface
type keep the system readable online and offline.

The launch screen is a paper-world poster with a clear Journey action,
distinct Classic/Daily/Weekly/Tutorial choices, compact flight setup, and
returning-player context. Hangar is a workshop, Journey is a travel journal,
and the result screen is a flight receipt. Flight UI protects the center and
lower-middle of the playfield.

Motion: staged launch-screen entry, small paper-button lift on interaction,
and restrained route/reward reveals. Reduced motion removes nonessential
movement. Scenery remains subordinate to hazards and the player silhouette.

## Delivery plan

1. Rebuild the launch composition and shared visual system; organize CSS by
   ownership and add a production hero asset.
2. Redesign every existing screen: Hangar, Journey, route editor, settings,
   guide, pause, postcards, leaderboards, and flight results. Fix upgrade
   search focus and restore the missing group controls.
3. Add portable progress backup/restore with validated data, explicit preview,
   safe failure handling, and rollback; preserve existing storage contracts.
4. Refresh live scenery, plane presentation, HUD, feedback, and audio cues;
   retain tested bank/altitude/Tuck physics and fairness invariants.
5. Harden graphics/native recovery, measure the result, and verify the whole
   integrated experience before committing, pushing, and deploying.

## Acceptance criteria

- All existing modes, upgrades, purchases, claims, editor layouts, Journey
  chapters, mastery, postcards, boards, and saved settings remain functional.
- A returning profile retains wallet, purchases, history, and progress.
- Search accepts a complete query without losing focus; filters work and
  empty results offer a clear recovery path.
- Backup validates version, keys, sizes, and stored values; invalid input
  cannot partially overwrite a profile. Restore failure rolls back changes.
- Primary menu actions fit 320×568, 390×844, 844×390, and desktop viewports;
  longer panels scroll deliberately. Keyboard, touch targets, contrast,
  dialog focus, and reduced motion remain usable.
- Hazards, updrafts, stars, plane silhouette, and the altitude resource read
  clearly in real flights across representative zones.
- Unit tests, development and production browser lanes, builds, bundle
  budgets, and generated iOS parity pass. iOS simulator and production smoke
  are inspected. Hosted GitHub checks may remain blocked by account billing.

## Observed baseline findings

- A centered menu card hides most of the world illustration and gives modes
  equal visual weight without explaining their differences.
- Hangar upgrade search is laid out as a result card and its input handler
  recreates the focused field on each keystroke.
- Upgrade-group navigation is constructed in `renderUpgrades` but never
  appended, making an implemented filter unavailable to players.
- UI colors, shadows, and rounding differ across the menu, Hangar, Journey,
  dialogs, and gameplay overlays.
- No portable profile backup exists; progress depends on one local browser
  storage origin.

## Asset brief

Built-in image generation: a wide cut-paper diorama of a cream origami plane
over a small paper coast, with calm pale-blue negative space at left for
interface type. Flat colored stock, visible fibres and folds, hard layered
shadows, ink/rust accents, no text or UI. Store the selected production asset
under `public/assets/` and keep this prompt as its provenance.

## Delivered and verified

- Rebuilt the launch poster and themed every existing screen, flight cues,
  install/update prompts, and the native loading card. CSS now has explicit
  ownership by flight, screens, Journey, adaptation, and shared theme.
- Fixed upgrade-search focus, restored group filters, and added result counts
  and an empty-result recovery path.
- Added portable saves, file/text preview, download/copy, restore rollback,
  and persistent undo. Existing profiles containing the retired `arDesk`
  boolean remain compatible without restoring that removed feature.
- Added independently seeded, non-colliding folded scenery across six zones
  and short paper-rustle cues. Existing flight physics and fairness remain.
- Added native web-content termination recovery and excluded generated
  artifacts from Vite's source watcher.
